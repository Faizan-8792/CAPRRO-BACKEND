# Commit-bound deploy archive and AST secret gate (final review)

This change adds a Hostinger archive builder that selects one Git commit, verifies runtime membership, modes and blob bytes, scans deployable content, and publishes through a same-directory temporary ZIP. It also replaces nodemon with Node’s watcher and pins Acorn 8.18.0 for the JavaScript scanner. The archive-integrity checks are strong, but the reviewed state cannot pass its own preconditions and the secret gate has confirmed escape paths. **Watch for:** **blocker, confirmed** — the scanner is untracked while the builder requires it in HEAD; **high, confirmed** — unscanned file types/manifests and syntax-local AST matching can admit credentials; **high, confirmed** — scanner verification rejects normal CRLF checkouts yet races later worktree execution.

**Verdict**: NEEDS_CHANGES

## High-level view

The runtime ZIP is derived from a resolved commit and checked against that commit’s file set and blob IDs. The current four-file change is not buildable: tracked edits trip the clean-tree gate and the scanner has no committed blob (**blocker, confirmed**).

Secret scanning has two coverage gaps. PowerShell skips non-enumerated extensions and exempts package manifests from strict identifier checks, while the AST scanner recognizes only direct assignments/properties and a few expression shapes; both admit realistic hardcoded JWT secrets (**high, confirmed**).

Scanner trust is asymmetric. Raw worktree hashing can reject a clean Windows checkout under the repository’s line-ending settings, but the verified path remains mutable until its later execution and Acorn is loaded from mutable `node_modules` (**high, confirmed**).

The child protocol is fail-closed but can stop making progress. Sequential stdout/stderr draining deadlocks once stderr fills, there is no timeout, and the 32 MB limit applies only after PowerShell has retained and duplicated the sources (**medium, confirmed**).

Same-environment `git archive` output was reproducible and the same-directory move is an atomic publication boundary. Abrupt termination can leave stale partials (**low, confirmed**), and the package does not declare the Node floor implied by its new tooling (**low, confirmed**).

### Current tree cannot satisfy the release gate

`tools/make-deploy-archive.ps1:201-209` refuses tracked differences from HEAD. The package files and builder are modified, while `tools/scan-deploy-secrets.mjs` is untracked and has no blob for the mandatory check at lines 221-249. The builder reproduced this refusal before creating an archive. This is a **blocker, confirmed**: add the scanner and commit all four files together, then rerun validation from the clean commit.

### Runtime allowlisting leaves content unexamined

The archive accepts every regular file below `src` and `public`, but decoding stops at the extension gate in `tools/make-deploy-archive.ps1:35,432`. `public/app.js.map`, SVG, INI/properties files, extensionless configuration, and `.npmrc.backup` are packaged without provider or identifier scanning; direct probes confirmed the `.map` and `.npmrc.backup` bypasses. The mandatory package manifests are decoded but excluded from strict config checks at lines 446-449, allowing a `package.json` command such as `JWT_SECRET=hardcoded-secret node src/server.js`. This is **high, confirmed**: reject unknown runtime extensions or scan every regular blob with bounded binary/text handling, and give package scripts/config a named-secret policy.

### AST matching misses common value flow

`tools/scan-deploy-secrets.mjs:164-218` recognizes variable declarators, assignments, object properties, and logical/conditional fallbacks; `containsHardcodedValue` handles only direct expression shapes. Executed probes returned exit 0 for an alias assigned to `JWT_SECRET`, split short literals, destructuring and parameter defaults, a class field, `Buffer.from(...).toString()`, and `process.env["JWT" + "_SECRET"]`. Short and numeric values also evade the string predicate. This is **high, confirmed** because arbitrary JWT secrets have no provider prefix to catch them; add conservative constant/taint handling for aliases, `AssignmentPattern`, `PropertyDefinition`, template expressions, computed names and common conversions.

The same shortcuts reject `const JWT_SECRET = "not-configured"` and report `target[JWT_SECRET] = "ordinary-value"` as though the computed identifier were the literal property name. Strict JSON/YAML checks also reject safe variable references by name. These are **low, confirmed** false positives; distinguish computed member keys and define an explicit sentinel/reference policy.

### Scanner verification is neither checkout-stable nor execution-stable

The builder hashes raw worktree bytes at `tools/make-deploy-archive.ps1:241-248`. This repository has `core.autocrlf=true`, no `.gitattributes`, and tracked text files already present as LF blobs with CRLF worktrees, so a fresh checkout can be Git-clean while the scanner’s raw hash differs. The scanner is then invoked only at lines 466-469, after archive generation and per-file hashing, leaving a time-of-check/time-of-use window; Acorn is also loaded from mutable `node_modules`, and its version string does not establish installed-code integrity. This is **high, confirmed**. Run scanner bytes materialized from the commit, isolate inherited code-injection settings such as `NODE_OPTIONS`, and require or verify a lockfile-integrity Acorn installation.

Git reads do not disable replacement refs. Git normally honors `refs/replace`, while `rev-parse` can still print the original name; if index/worktree state matches that view, `ls-tree` and `archive` can agree on substituted content labeled as the original commit. No replacement refs are currently present, making this **medium, likely** rather than active corruption. Apply `--no-replace-objects` or `GIT_NO_REPLACE_OBJECTS=1` consistently.

### Scanner failure handling can hang or exhaust the parent

`Invoke-JavaScriptSecretScan` writes the payload, then reads stdout before stderr at `tools/make-deploy-archive.ps1:159-165`. The scanner emits findings to stderr while stdout stays open until exit. A batch of 10,000 findings failed to exit within 10 seconds and exposed only 4,071 stderr characters after forced termination, confirming backpressure. This is **medium, confirmed**: drain both streams concurrently, impose a deadline, and kill the process tree on timeout.

The 32 MB cap at `tools/scan-deploy-secrets.mjs:5,17-21` runs only after PowerShell has retained every JavaScript source, serialized UTF-16 JSON, and allocated UTF-8 bytes at `tools/make-deploy-archive.ps1:136-161`. Expanded archive entries and aggregate input have no parent-side bound. This is **medium, confirmed**; enforce limits while reading and stream or batch bounded payloads.

### Atomic publication leaves crash debris

The same-directory move at `tools/make-deploy-archive.ps1:476` keeps partially validated ZIPs out of the final path, and two same-commit archive streams had identical hashes in this environment. Cleanup at lines 482-485 targets only the current timestamp/PID path, so termination or killing the confirmed hang can leave older `.partial-*` files. This is **low, confirmed**; collect safely matched stale partials by age. Cross-version reproducibility remains untested because Git/zlib versions are not pinned.

### Node compatibility is implicit

`package.json:9,28` introduces `node --watch`, while the scanner uses top-level await and `Array.prototype.at` (`tools/scan-deploy-secrets.mjs:143,239`) without an `engines` declaration. This is **low, confirmed**: older installations can succeed and then fail development or scanning. Declare the Node floor and document that archive builds require dev dependencies because Acorn is not a production dependency.

### Executed checks and untested release path

The exact UTF-8 byte protocol passed all 148 runtime JavaScript files with a 1,913,030-byte payload. Node and PowerShell syntax checks passed, `npm ls` resolved Acorn 8.18.0, `npm audit --audit-level=low` found zero vulnerabilities, and `git diff --check` passed. Focused bypass, false-positive, manifest/extension, deadlock, line-ending and current-state probes produced the findings above.

Not tested: a successful end-to-end build from the proposed commit, because the scanner is untracked and tracked files are dirty; a fresh checkout reproducing the CRLF mismatch, because that would mutate repository state; archive reproducibility across Git/zlib versions; cleanup under actual process or machine termination.
